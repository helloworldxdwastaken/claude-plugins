# Two-pass recheck protocol

Use this protocol for the artifacts produced or reviewed by this skill. There are two verification passes, not an endless chain of reviewers.

## Pass 1 — check the work

The worker checks actual output bytes against raw inputs, reference roles, the requested edit and applicable contracts. Save artifact/map/config hashes, exact commands or inspection methods, observed results, coverage and unresolved findings. A generated report, status flag or cached receipt is not proof that the current files passed.

## Pass 2 — reopen and challenge the final result

Freeze the candidate. Use a separate checker agent when available, with raw sources, final artifacts, requirements and access needed for local verification. Let it make its own observations before sharing the first verdict. If delegation is unavailable, run a distinct pass using an independent method and disclose the reduced independence; do not claim a second agent ran.

The second checker recomputes final hashes, opens the actual files/player, checks boundary cases and independently reproduces critical conclusions. Use native first/last frames, both sides of cuts/joins, speech onsets/ends and risk-specific interior samples. For video inspect face/profile, garment features, room layout and temporal continuity. For original-performance voice conversion compare actual original/isolated/final words and target voice. For direct TTS compare the approved text against the actual final take and target voice; do not require an isolated source lane that was never part of that task. If source-word fidelity is required but source audio is missing, leave that check unassessed. In either branch verify placement, quiet windows, joins and actual lip observations where required. For mapping independently recalculate native coordinates and decoded counts/PTS. For integration challenge one-voice and authoritative-result eligibility using isolated replay/fault evidence and confirm the player selected the frozen candidate.

Running the same command twice or rereading a summary is not an independent second check. Structural/hash checks cannot substitute for missing listening, viewing or runtime evidence. If a required check is inaccessible, mark it not assessed and keep that dimension held; continue independent checks that can run.

## Repair and stop

Reconcile disagreements against raw evidence. Fix only within the task's existing authorization and budget. After changes, invalidate the affected prior checks, rerun affected failures and boundary/neighbour coverage, then repeat the second pass on final hashes. Cross-shot identity/layout or changed timing may require checking dependent intervals too. Keep one cumulative spend/retry ledger; checking again does not authorize provider work, model downloads, live activation or state changes.

Default to at most two repair/recheck cycles unless the user authorized a larger bound. Stop earlier when blocked by missing source, capability or budget. Deliver unresolved findings rather than quietly weakening acceptance. The inspector reports repairs unless implementation is separately authorized.

## Check records

Save separate records for pass1 and pass2: reviewer/method, input and final hashes, mapping/config version, requirement, evidence path, actual result, inspected coverage, limitations and status. Keep old results as history. Recompute hashes at handoff; a changed artifact invalidates affected signoff. Report pass within inspected coverage, mismatch/hold, not visible and not assessed separately. Never call the result fully checked when a required dimension remains unassessed.
